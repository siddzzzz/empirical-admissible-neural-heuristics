# Hierarchical Reinforcement Learning for Rubik's Cube Solving (H-DAVI)

This repository implements a **Hierarchical Reinforcement Learning (HRL)** framework to solve a 2x2 Rubik's Cube. It uses **Hierarchical Deep Approximate Value Iteration (H-DAVI)** to train a neural network heuristic, which is then paired with A* search to solve scrambled cubes.

The project also features a premium **Neural Brain Introspection Dashboard** to visualize what the network has learned, check heuristic calibration, and view sticker-level attention saliency maps.

---

## 🧠 Core Algorithm: Hierarchical Deep Approximate Value Iteration (H-DAVI)

### 1. Neural Heuristic Network (ValueNet)
Our agent uses `ValueNet`, a multi-layer feedforward neural network that acts as the heuristic function $h(s)$ for A* search.
* **Input Representation**: A 144-dimensional one-hot vector representing the state of the 24 stickers on the 2x2 Rubik's Cube (24 stickers $\times$ 6 possible colors).
* **Output**: A single scalar representing the estimated remaining distance (in terms of primitive moves) to the solved state.
* **Architecture**: 4 fully-connected layers with hidden dimension sizes: `144 -> 256 -> 256 -> 128 -> 1`. Activations are `ReLU`.

### 2. Bellman Update Equation (Approximate Value Iteration)
The network learns the optimal cost-to-go function $V^*(s)$ via the Bellman optimality equation. For any state $s$:
$$V(s) = \min_{a \in \mathcal{A}} \left[ c(s, a) + V(s') \right]$$

Where:
- $\mathcal{A}$ is the set of 18 primitive actions (90° and 180° turns of the faces).
- $s'$ is the next state resulting from taking action $a$ in state $s$.
- $c(s, a) = 1.0$ is the uniform step cost for primitive moves.
- If $s'$ is the solved state, $V(s') = 0.0$.

### 3. Training Loop Details
- **Optimization**: AdamW optimizer with a learning rate of $1\times 10^{-3}$ and Huber Loss (`nn.HuberLoss`).
- **Target Network**: To stabilize learning, target values are computed using a target network $V_{\text{target}}$, which is updated with the online network's weights every 100 steps.
- **Bellman Target Formulation**:
  $$y = \min_{a \in \mathcal{A}} \left( 1.0 + V_{\text{target}}(s') \right)$$
  If the current state itself is solved, $y = 0.0$.
- **Memory Fixes**: The training loop runs highly optimized tensor operations. It converts state batches directly in PyTorch using `torch.nn.functional.one_hot` and `torch.from_numpy` (avoiding memory allocations on the heap), frees unused gradient memories using `optimizer.zero_grad(set_to_none=True)`, and runs explicit garbage collection (`gc.collect()`) after solver evaluations.

### 4. Curriculum Learning
To learn effectively from scratch, the training employs curriculum learning:
- The scramble depth starts at 1 random move.
- Every 500 steps, the model is evaluated on 100 random scrambles at the current curriculum depth.
- If the solver achieves a success rate $\ge 90\%$, it **levels up** and increments the scramble depth by 1 (up to God's Number of 14 for the 2x2 cube).

## 🔍 Search & Hierarchy: Batched A* Solver

During evaluation and solving, the heuristic $h(s)$ generated by `ValueNet` is combined with A* search.

### 1. Hierarchical Branching (Macros)
The A* search can branch on both:
- **18 Primitive Actions**: Standard $90^\circ$ and $180^\circ$ face turns.
- **Compiled Hierarchical Macros**: Reusable move sequences compiled into single-step permutations. This allows the search to bypass local minima and jump across the state space.

### 2. Batched Heuristic Evaluation (15-20x Speedup)
Standard A* search suffers from high neural network forward pass overhead since nodes are typically expanded one by one. 
To bypass this bottleneck:
1. When a node is expanded, all valid child candidate states (up to 18 primitive transitions) are generated.
2. The candidates are filtered against the visited list.
3. The remaining candidates are batched together and sent through the neural network in a **single forward pass**.
4. This results in a **15–20x search speedup** on CPU.

## 🎨 Interactive Dashboard & Introspection

Run the Streamlit app to interact with the trained agent and inspect its "brain":

```bash
streamlit run dashboard/app.py
```

The dashboard contains two main workspaces:
1. **🧩 Solver Dashboard**: A visual 2D unfolded view of the cube. Manually scramble the cube, take individual moves, or click **AI A* Solve** to let the agent search and display the solution path (highlighting primitive vs macro steps).
2. **🧠 Neural Brain Introspection**:
   - **Sticker-Level Attention (Saliency Map)**: Backpropagates gradients from the value estimate through the network to the input stickers. Highlights which stickers are most important to the model's distance estimate.
   - **Heuristic Calibration Curve**: Profiles the model across all scramble depths (1 to 14) to compare true scramble depth vs. predicted distance and calculates the **Admissibility Rate** ($h(s) \le \text{true\_cost}$).
